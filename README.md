## 中文说明

GPTSMS CDK SMS Receiver 是一个基于 CDK 的短信接码网站。用户无需注册或登录，只需要输入站点生成的 CDK，即可从上游 SMSPool 获取号码并等待短信。后台提供配置、CDK 生成、号码/会话查看和审计日志功能。

### 主要功能

- CDK 兑换号码：用户输入 CDK 后获取一个可用号码。
- 自动轮询短信：前端只拿到必要字段，后端负责调用上游接口。
- 一次成功即失效：CDK 成功收到短信后立即标记为不可用，防止重复接码。
- 号码复用：同一号码最多可成功使用 3 次，可按配置调整。
- Resend 支持：已使用过的号码可通过上游 resend 重新接收短信。
- 冷却控制：当上游返回 resend 冷却时间时，系统会记录并在冷却结束后再使用。
- 超时换号：超时未收到短信时，用户可更换号码。
- 失败退款：新购买号码若未成功收到短信，可按规则调用上游退款接口。
- CDK 查询记录：用户可用自己的 CDK 查询绑定号码和已收到的短信内容。
- 管理后台：配置上游、生成 CDK、查看号码、会话和审计日志。
- 中英文界面：前台和后台均支持中文/英文切换。

### 安全设计

本项目默认按生产环境安全要求设计：

- 不公开项目根目录，只静态暴露 `public/`。
- `private/` 后台页面不作为静态目录公开，只通过配置的管理路径访问。
- 上游 API Key 不返回给前端，并加密保存到本地数据文件。
- 前端 API 只返回页面必须字段，不返回上游 orderid、raw 响应、内部账号 ID 等数据。
- 管理 API 需要登录后的 HttpOnly Cookie；除登录接口外不接受 `x-admin-token`。
- `sessionToken` 只允许通过 `x-session-token` Header 传递，不接受 URL/body token。
- CDK 错误统一返回 `CDK 不可用`，避免枚举 CDK 状态。
- API 响应默认 `Cache-Control: no-store`。
- 使用 Helmet 设置常见安全响应头和 CSP。
- 使用 rate limit 限制 CDK、session、admin 接口频率。
- 生产环境必须配置强随机 `ADMIN_TOKEN` 和 `APP_SECRET`，否则拒绝启动。
- 审计日志记录后台登录、配置变更、CDK 操作、用户兑换、换号、接码等事件。

> 注意：本地数据文件仍会保存号码、CDK、短信内容等业务数据。生产环境应限制文件权限，并做好加密备份和服务器访问控制。

### 生产部署建议

建议使用 Caddy 或 Nginx 反向代理到本地监听端口：

```caddy
sms.example.com {
    encode gzip
    header {
        X-Frame-Options DENY
        X-Content-Type-Options nosniff
        Referrer-Policy no-referrer
    }
    reverse_proxy 127.0.0.1:3000
}
```

建议 systemd 加固项：

```ini
NoNewPrivileges=true
PrivateTmp=true
PrivateDevices=true
RestrictSUIDSGID=true
LockPersonality=true
SystemCallArchitectures=native
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/path/to/app/data
```

## English

GPTSMS CDK SMS Receiver is a CDK-based SMS receiving website. Users do not need to register or log in. They enter a CDK generated by the site, receive a phone number from the upstream SMSPool service, and wait for incoming SMS messages. The admin panel provides upstream configuration, CDK generation, number/session inspection, and audit logs.

### Features

- CDK-based number redemption.
- Automatic SMS polling through the backend.
- One successful SMS consumes the CDK permanently.
- Number reuse with configurable maximum successful uses, default `3`.
- SMSPool resend support for previously used numbers.
- Resend cooldown tracking based on upstream responses.
- Timeout and number replacement flow.
- Refund attempt for newly purchased numbers that never received SMS.
- CDK record lookup for the same CDK, including bound number and received SMS text.
- Admin panel for configuration, CDK generation, accounts, sessions, and audit logs.
- Chinese and English UI support.

### Security Notes

The project is designed with production-oriented security defaults:

- Only `public/` is exposed as a static directory.
- Admin files under `private/` are not exposed as a general static directory.
- Upstream API keys are never returned to the frontend and are encrypted at rest.
- Public frontend APIs return only the fields required by the UI.
- Public APIs do not return upstream order IDs, raw upstream responses, internal account IDs, pool/service metadata, or refund details.
- Admin APIs require a login cookie with `HttpOnly`, `SameSite`, and production `Secure` attributes.
- Except for the login endpoint, admin APIs do not accept `x-admin-token`.
- Session tokens are accepted only through the `x-session-token` header, not URL or request body.
- CDK errors are intentionally generic to reduce enumeration risk.
- API responses use `Cache-Control: no-store`.
- Helmet and rate limits are enabled.
- Production requires strong and distinct `ADMIN_TOKEN` and `APP_SECRET` values.
- Audit logs record admin login, configuration changes, CDK operations, redemption, number changes, and SMS receipt events.

> Note: the local data file may still contain business data such as CDKs, phone numbers, and SMS text. Restrict file permissions and protect backups in production.
